How It Works

A closer look at clients, servers, DNS, and the web request-response process.

The core process

From a click to a webpage

When you enter a website address, the browser (client) communicates with a server to retrieve the information needed to display the page.

Original diagram showing the basic request-response relationship.

  1. Enter a URL: The browser identifies the resource that you want.
  2. Find the server: DNS helps translate a domain name into an IP address.
  3. Send a request: The browser establishes a connection and sends an HTTP or HTTPS request.
  4. Process the request: The server finds or generates the requested resource.
  5. Return the response: The server sends a status code, headers, and possibly content such as HTML.
  6. Display the page: The browser processes the response and may request CSS, images, or other assets.

Understanding requests and responses

Client → Server

HTTP Request

The client includes a method such as GET or POST and identifies the requested resource.

Example: a browser requests a homepage.

Server → Client

HTTP Response

The server returns a status code and, when appropriate, a response body such as HTML or JSON.

Example: the server returns a webpage and status 200.

StatusMeaningExample
200Successful requestPage loaded successfully
404Resource not foundPage address does not exist
500Server-side errorServer fails while handling request

Where we see it every day

Online Banking

A banking app requests balances and transactions from secure backend services. Authentication and access controls help protect account information.

Video Streaming

A streaming client requests video data. Remote servers and content delivery networks provide the content as playback continues.
